Content model and relationships Represent these concepts in the UI; this is a UX model, not a database implementation mandate for Stitch. - **Professional Identity:** profile, biography, contact links, positioning. - **Project:** software system or piece of work with case study. - **Skill:** technology, technique or capability. - **Claim:** statement about capability, contribution, process or outcome. - **Evidence:** item/explanation supporting a claim or describing project work. - **Artifact:** inspectable output/reference such as repository, demo, screenshot, document or test report. - **Experience:** employment, education or relevant record. - **Certification/Learning Record:** course or credential with explicit type. - **Page Section:** structured block composing a public page. - **Media Asset:** image/file reference with metadata and alt text. - **Contact Message:** visitor message, subject to real backend handling later. - **Navigation Item:** configurable header/footer link. - **Activity Record:** content-management event. Relationships: - Projects connect to skills, claims, evidence and artifacts. - Claims connect to supporting evidence and optionally projects. - Evidence connects to projects, claims, skills and artifacts. - Artifacts can be referenced by multiple evidence records. - Skills link to projects/evidence where demonstrated. - Public visibility and evidence access are separate fields. - Public claims without evidence trigger a quality warning. - Deleting referenced content warns and offers archive/unlink alternatives. # 9. Prototype interaction requirements Every visible control must have a defined outcome; do not render dead buttons. **Navigation:** public header/footer, project cards, breadcrumbs, admin sidebar, preview links all navigate to the intended route.
